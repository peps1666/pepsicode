# 执行轨迹与失败恢复

顶部可在「对话」和「执行轨迹」之间切换。对话完成后，工具过程默认收起，失败数量和「查看轨迹」入口仍然保留。轨迹按轮次展示用户输入、模型回复、进度、工具调用、请求重试及项目验证；可以搜索或仅查看异常，点击记录查看参数、输出、调用 ID 和真实耗时。

没有修改、没有检查命令或没有收集到测试时，验证状态记为「未运行」，放在轨迹中查看，不在答案后附加固定提示。实际验证失败和输出仍会保留。每轮最后一条助手消息携带对应验证报告，历史会话也能恢复。

## 数据与关联

- 工具事件使用模型提供的调用 ID 配对；并行调用可以按真实完成顺序更新界面，模型历史继续按原调用顺序存储。
- 起始时间使用 epoch 毫秒，耗时使用单调时钟。历史数据未记录耗时时显示「—」，不根据会话加载时间推算。
- 旧会话缺少调用 ID 时，仅使用同名工具的 FIFO 兼容关联；带 ID 但无法匹配的结果保持独立，避免配错结果。
- 调用参数和结果来自已有公开执行记录；系统提示、内部恢复指令和模型签名思考块不显示在轨迹中。较长输出沿用现有工具输出截断预算。
- 默认显示最近 200 条匹配记录，可以加载更早的记录。检查历史时暂停自动跟随，避免新记录打断阅读。

## 失败恢复

- 工具失败仍作为工具结果返回模型，并附带内部恢复指导：检查错误、当前文件状态及是否部分完成，再选择修正参数或其他工具。权限拒绝、取消及等待用户输入不会触发这一指导。
- 「继续处理」会发送一条可见的后续消息，让模型基于现有历史继续排查；它不是直接重放失败的写文件或命令。运行中禁用此入口。
- 流式模型请求在尚未收到响应流时，对连接问题、限流及暂时性服务错误执行退避重试，默认最多 4 次，沿用 `PEPSI_CODE_MAX_RETRIES`。重试期间可以停止；鉴权错误不重试，已经开始返回内容的流不会被重新发送。
- 这些机制提供恢复上下文和有限重试；最终是否能完成仍取决于具体错误与模型后续动作。失败不会被改写成成功。

## 验证

v2.0.4：客户端 64 项、后端相关 166 项回归通过（执行与协议等 98 项，计划/Hook/分支/配置边界 68 项）。真实 ZIP 验收使用本地测试服务：先返回 503，再让工具读取不存在的文件、读取正确文件、写入一次结果并完成回答；检查轨迹、真实 ID/耗时、无检查命令状态和「继续处理」请求，确保旧工具没有被重放。真实浏览器另外验证搜索、异常筛选、保存历史恢复与窄窗口布局。

界面组织参考本机 dsh 的 `ui-trajectory` 所采用的轮次记录表和局部检查器，使用本项目现有的 React、会话协议和执行器实现，没有引入其运行时依赖。
