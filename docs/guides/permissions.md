## 权限模式

点击桌面输入框左下角的「权限」，或输入 `/permissions` 打开权限菜单，当前模式后显示 `√`。终端中用 ↑/↓ 选择、Enter 应用、Esc 返回。带参数命令仍保留供脚本使用。

| 模式 | 行为 |
| --- | --- |
| 每次询问（`ask`） | 项目内文件读取和搜索直接放行；文件编辑、本地命令执行、项目外路径及未声明只读的外部/MCP 工具均需确认 |
| 自动审批（`auto`，新会话默认） | 项目内文件编辑与工作区内常规开发命令（测试、构建、本地 Git 操作、受管 Worker 运行等）自动放行；高风险/破坏性命令（如 `rm -rf`、`git push`、`git reset --hard`、`git clean`、`chmod 777`、`sudo`、网络传输、包发布、容器变更）、项目外路径访问及未声明只读的 MCP/外部修改仍需确认 |
| 完全信任（`full_access`，高风险） | 文件访问（含项目外）、编辑、命令及外部/MCP 工具均免权限确认 |

模式随会话保存，恢复会话时恢复选择。旧会话或历史工作区默认配置中的 `trust_commands` 会自动映射为 `auto`（不会静默升级为 `full_access`）；QQ 通道配置的 `read_only` 以及历史只读会话继续保留只读边界。Plan 是独立的规划状态，始终保留只读边界和计划审批，退出后回到所选权限模式。完全信任也不会取消 Hook 的拒绝规则。

终端中可用 `/permissions default ask`、`/permissions default auto` 或 `/permissions default full_access` 为当前工作区的**新会话**设置默认模式。桌面端可在权限菜单中选择「将当前模式设为工作区默认」。设置只影响未来新会话，不改变当前会话；恢复旧会话时使用该会话保存的模式。未设置工作区默认值时使用 `auto`。工作区默认值保存在用户目录的 `~/.pepsi-code/workspace-permissions.json`，按规范化的工作区绝对路径区分。

**风险提示：自动审批和完全信任都是应用层审批策略，不是操作系统级沙箱；被批准运行的本地程序拥有当前用户的全部权限。** 自动审批模式会拦截已知高风险、破坏性、提权和远端变更命令，但无法阻止已获准运行的脚本本身访问网络或项目外文件；仅在信任当前工作区代码和任务时使用。

命令审批中的“拒绝一次”会在当前运行会话内记住该精确命令和工作目录；即使切换到 `auto`，相同命令仍会被拒绝，重新加载会话后不保留。“始终拒绝”会持久保存，切换到 `auto` 也不会撤销它。

## 安全说明

- 请在提交项目 Hook 前进行代码审查；项目 Hook 的信任是安全边界，不是形式提示。
- 不要把密钥写入 `hooks.json`、README 或仓库。
- `command` Hook 不会绕过命令权限，也不会在 Plan 模式执行。
- 后台 Hook 任务在进程关闭时会等待有限时间，未完成任务会被取消。
- `.pepsi-code/hooks.local.json` 适合本机差异，不应提交。
- 自动模式和命令免确认都是应用层审批策略，不是操作系统级沙箱；被批准运行的程序拥有当前用户的全部权限。
- 文件、进程、外部调用的统一执行边界，共享预算/取消、版本编辑与中断恢复见 [Harness 执行边界](../architecture/harness-boundaries.md)。
