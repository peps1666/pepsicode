# Harness 执行边界

本次改动把审批落实到副作用的执行入口，并为一次任务建立共同的预算、取消和恢复记录。内置工具、验证命令、子代理和命令 Hook 共用这些入口。第三方 Python 扩展属于宿主可信代码；Python API 不构成对任意扩展代码的隔离。

## P0：审批必须发生在副作用之前

| 边界 | 执行入口 | 可验证行为 |
| --- | --- | --- |
| 文件 | `execution/filesystem.py` 的 `FILES` | 解析真实路径、检查操作意图、审批 diff，再发布修改；批量编辑、Notebook、重命名、记忆文件共用入口 |
| 进程 | `execution/process.py` | 所有内置进程工具和 Git/Docker/验证命令走相同审批；实际启动 SandboxBackend 返回的 argv |
| 外部服务 | `execution/external.py`、MCP 工具适配器 | HTTP 修改和未声明只读的 MCP 调用要求审批；拒绝后不发送请求；MCP 丢失响应后不自动重放 |

`allow_once` 只授权一次调用，不再写入整个会话的许可缓存。一次工具内部重复检查同一路径时，授权仅限该工具的当前操作意图和权限模式。命令长期许可使用真实 cwd 和结构化 argv 作为键，避免参数拼接歧义以及跨目录复用。

HTTP 修改审批展示目标和操作。跨目标重定向不能继承原修改授权。`web_fetch` 继续检查初始 URL 和每次跳转的地址限制。HTTP 方法本身无法证明远端没有副作用：GET 的只读语义和 MCP `readOnlyTools` 声明都需要服务遵守。

### 操作系统隔离的实际范围

默认 `processSandboxMode` 是 `danger-full-access`，表示**应用层审批，通过后的程序拥有当前用户的权限**。它不能阻止被批准的 Python、Shell、Git Hook 或 Docker 访问工作区外资源。

当前内置 LocalSandboxBackend 没有内核隔离能力。选择 `workspace-write` 或 `read-only` 时，它会拒绝启动，不能降级成直接运行。自定义后端必须返回实际封装的 argv 和 `full` enforcement；仅环境清理等 `partial` 能力不足以满足限制模式。本次没有新增 Windows/Linux 原生隔离后端。

MCP 的服务启动和连接来自宿主配置。配置中的程序、语言服务器和自定义扩展是可信计算基的一部分。工具能力声明不能约束已经获准运行的任意代码。

## P1：一个任务只有一个执行所有者

`ExecutionScope` 为主循环、子代理、压缩摘要和验证重试共享：

- 任务链身份和父子关系，以及共同的 JSONL 执行日志。
- 模型请求次数上限和成本跟踪。子任务及摘要不能各自重置预算。
- 取消信号和任务截止时间。后台 Hook 同时观察自己的取消和父任务取消。
- 结果不明的操作清单；子任务出现未知结果时，父任务也不能继续修改。

模型请求在实际提供者入口计数，包含重试、fallback、摘要和流式请求。并发的受预算请求串行核算，避免多个请求同时花费同一笔余额。使用量只计入一次；有金额限制且使用量缺失时，后续请求拒绝继续。

`budgetLimitUsd` 是基于本地价格表和 token 使用量的估算护栏。发送前还检查当前请求的保守估计；它可能提前拒绝请求，不承诺供应商账单的精确硬上限。`modelRequestLimit` 提供与价格表无关的请求次数上限。

前台命令超时或取消后，会停止并等待它拥有的进程树再返回。Windows 使用 Job Object，POSIX 使用独立进程组。已启动的程序仍可能留下文件或远端副作用，因此取消不会被描述为回滚。显式后台命令属于会话资源，会话关闭负责清理；它的启动成功不等于工作完成。网络连接建立受超时限制，响应读取支持取消；这不是对所有原生库阻塞调用的强制抢占。

### 编辑版本和原子发布

文件读取记录内容 SHA256。编辑时检查预期版本，审批完成后再次检查，写临时文件并 flush/fsync，在替换前再次验证目标与版本，最后 `os.replace`。主会话的读取版本保留到后续轮次，编辑器内部读取不会抹掉旧版本；发现过期后需要显式重新读取。子任务保有自己的版本视图。同一物理路径上的协作写入使用进程内锁和共享临时目录中的 OS 文件锁；跨进程锁协调要求相同的临时锁目录。

这能拒绝“读取之后，别人已修改”的覆盖，并保证单文件发布的原子性。多文件操作可能部分完成；它不是跨文件数据库事务。外部程序不遵守文件锁，路径检查也不是内核级句柄隔离，仍有与恶意外部进程竞争的限制。

### 结果不明和恢复

工具结果区分 `blocked`、`cancelled`、`timed_out`、`unknown` 等状态。审批拒绝发生在分发前；分发后失去响应、超时或部分写入失败，不能当作“什么也没发生”。

日志位置：`<workspace>/.pepsi-code/executions/<task-id>.jsonl`。工具分发之前写入并 fsync `tool/started`；完成后记录结果、输出和副作用状态。文件和进程也分别记录准备、提交或完成事件。会话在第一次副作用前保存日志指针，恢复时只读取该会话指向的工作区日志，不扫描其他会话。

恢复发现未完成或未知结果时：

1. 把待核对调用带入新任务日志，注入恢复说明，阻止新的文件修改、进程和外部修改。
2. 使用 `execution_status` 的 `inspect` 查看调用，读取相关文件或查询外部实际状态。
3. 使用 `execution_status` 的 `reconcile` 提交核对证据并取得审批，再解除阻塞。全权限模式视为已有授权；只读/Plan 模式不能解除阻塞。

解除阻塞只记录核对决定，不重放、不撤销原操作。日志损坏或不可读取会保守要求核对。只有最后一条没有换行的截断记录可以忽略；已经提交的损坏记录不会静默跳过。没有用户接手权限的自动运行会保持阻塞。

### 请求重建和日志可信度

`model/prepared` 保存实际发出的请求体：system、消息、临时 Hook 上下文、工具 schema、模型及生成参数；保存 endpoint 和 request ID，**不保存认证请求头**。完成记录关联使用量，流式请求也受同一入口管理。它可用于重建模型输入和定位失败，不保证供应商再次产生同样输出。

请求和工具记录可能含源码、用户文本及工具参数中的敏感信息。日志已加入 `.gitignore`；普通文件工具不能修改执行日志目录。获准运行的本地程序仍能修改文件，所以日志不是防篡改安全审计账本。清理策略应由运行者根据本地保存需求决定。

## 配置与验证

`settings.json` 示例：

```json
{
  "modelRequestLimit": 200,
  "taskTimeout": 600,
  "budgetLimitUsd": 2.0,
  "processSandboxMode": "danger-full-access"
}
```

`taskTimeout` 单位为秒，默认不设置；请求次数默认 200。次数和时间必须为正值，非法配置拒绝加载。金额预算仍取决于配置模型的本地价格估算。

离线边界回归：

```bash
python -m pytest -q tests/test_execution_boundaries.py tests/test_execution_recovery.py tests/test_request_budget.py
```

测试覆盖授权拒绝无文件/进程/网络副作用、直接调用工具、Plan/只读绕过、版本竞争、沙箱不可用拒绝运行、真实进程树取消、父子预算、恢复阻止重放和核对审批。AST 回归检查阻止内置工具重新引入直接进程/文件写入口。真实任务效果评测见 [task-evaluations.md](task-evaluations.md)；离线 smoke 不代表真实模型任务成功率。
