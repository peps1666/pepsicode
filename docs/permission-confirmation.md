# 输入框上方的权限确认

v2.0.6 将全屏遮罩权限弹窗改为输入框上方的确认卡片。卡片与输入框共用宽度、边距和圆角；对话仍可滚动，执行轨迹仍可切换。常用操作保持在底部，内容较长时卡片内部滚动。

## 参考依据

- 查阅本机安装的 Codex / ChatGPT 桌面版 `26.1013.4894.0` 中 `pending-request-item-panel` 和输入区固定内容组件：终端/文件身份行、确认问题、灰色命令预览、长命令折叠、批准与拒绝操作。这些是布局参考，本项目使用自己的 React 组件与视觉变量实现。
- [官方 Sandbox 文档](https://learn.chatgpt.com/docs/sandboxing) 解释沙箱边界和审批范围；该页面不是当前权限卡片的精确视觉规范。

## 行为

- 服务端决定是否请求审批，客户端只呈现其已有 choices，并原样提交 decision、prompt_id 和反馈。没有扩大权限，也没有新增后台自动批准。
- 主操作是「本次会话允许」和「拒绝」；「更多选项」保留长期允许/拒绝、本轮文件授权和拒绝附意见等现有决策。原后端 `allow_once` / `deny_once` 实际使用会话缓存，因此文案按真实行为标注，避免误称只批准一次。计划批准单独标成「批准计划」。
- 命令、路径与原始原因可以展开查看。命令预览仅折叠显示，不截断原始内容；Python 和未知命令的常见原因有中文说明，原文保留在详情。
- 出现请求时聚焦卡片，Enter 不默认批准，Escape 不默认批准或拒绝；可以正常 Tab 导航。没有全屏遮罩、背景模糊或焦点陷阱。
- 提交期间禁用重复操作。失败保留当前请求并展示错误，支持重试；旧请求的延迟响应不能清除后来出现的新请求。

## 验证

- 72 项客户端测试：覆盖实际 decision 映射、长期范围中文说明、显式点击、重复点击锁定、提交错误、反馈及旧响应竞争。
- 51 项相关后端测试：权限、审批桥接、取消、输入队列和会话。
- 真实 ZIP 使用本地 SSE 测试接口，发出确实需要审批的完整程序路径。批准前标记文件不存在；拒绝后仍不存在；对另一条命令批准后才生成标记文件。测试前后端均使用隔离用户目录。
- 真实浏览器检查卡片在输入框上方、对话不模糊、长命令展开、更多选项、Escape / Enter、820×680 窗口，并截图进行视觉检查。
