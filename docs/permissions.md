## 权限模式

点击桌面输入框左下角的「权限」，或输入 `/permissions` 打开权限菜单，当前模式后显示 `√`。终端中用 ↑/↓ 选择、Enter 应用、Esc 返回。带参数命令仍保留供脚本使用。

| 模式 | 行为 |
| --- | --- |
| 只读 | 允许文件读取、搜索和声明为只读的工具；拒绝编辑、命令执行及外部写入 |
| 自动（未设置工作区默认值时的新会话默认） | 项目内编辑免确认；本地进程、项目外路径及未声明只读的 MCP 工具按现有规则确认 |
| 命令免确认（`trust_commands`，高风险） | 本地命令默认免确认；内置工具访问项目外路径及外部工具继续按原规则确认 |
| 完全访问 | 文件访问、编辑、命令及 MCP 工具均免权限确认 |

模式随会话保存，恢复会话时恢复选择。Plan 是独立的规划状态，始终保留只读边界和计划审批，退出后回到所选权限模式。完全访问也不会取消 Hook 的拒绝规则。

终端中可用 `/permissions default trust_commands` 为当前工作区的**新会话**设置默认模式；用 `/permissions default auto` 改回自动模式。桌面端可在权限菜单中选择「将当前模式设为工作区默认」。设置只影响未来新会话，不改变当前会话；恢复旧会话时使用该会话保存的模式。未设置工作区默认值时使用 `auto`。工作区默认值保存在用户目录的 `~/.pepsi-code/workspace-permissions.json`，按规范化的工作区绝对路径区分。

**高风险：命令免确认会让模型以当前系统用户权限执行任意程序，包括 Python / Shell、网络请求和项目外文件访问。只在信任当前任务时使用。** 内置工具对项目外访问的审批不能限制本地命令。当前命令后端没有操作系统级沙箱，即使运行目录位于项目内，程序仍具有当前系统用户的权限。

命令审批中的“拒绝一次”会在当前运行会话内记住该精确命令和工作目录；即使切换到 `trust_commands`，相同命令仍会被拒绝，重新加载会话后不保留。“始终拒绝”会持久保存，切换到 `trust_commands` 也不会撤销它。

## 安全说明

- 请在提交项目 Hook 前进行代码审查；项目 Hook 的信任是安全边界，不是形式提示。
- 不要把密钥写入 `hooks.json`、README 或仓库。
- `command` Hook 不会绕过命令权限，也不会在 Plan 模式执行。
- 后台 Hook 任务在进程关闭时会等待有限时间，未完成任务会被取消。
- `.pepsi-code/hooks.local.json` 适合本机差异，不应提交。
- 自动模式和命令免确认都是应用层审批策略，不是操作系统级沙箱；被批准运行的程序拥有当前用户的全部权限。
- 文件、进程、外部调用的统一执行边界，共享预算/取消、版本编辑与中断恢复见 [Harness 执行边界](harness-boundaries.md)。
